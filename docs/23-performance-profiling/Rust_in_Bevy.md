# Rust in Bevy 23：迭代器成本与测量边界

性能问题很少能靠肉眼读出。先测量热路径，再决定是否值得改变数据布局或算法。

## 本章唯一主题

识别 Query/Iterator 的实际工作量，并用基准或 profiler 验证假设。

```rust
let visible = sprites.iter().filter(|sprite| sprite.visible).count();
```

- 这段代码遍历每个匹配实体；`count` 不会凭空得到缓存结果。
- 过滤器应尽量进入 Query，减少系统拿到后再丢弃的组件组合。
- `collect::<Vec<_>>()` 会分配；只有确实需要在迭代后保留集合时才使用。

## 设计用法

记录场景规模、帧时间、平台和测量方法。优化前后保持相同工作负载；否则数字无法比较。性能与正确性同等重要，先用测试守住规则再缩短热路径。

避免为了微小分配牺牲清晰数据边界；只有 profile 指向它时才优化。

## 练习

测量一个全体实体扫描系统，随后加入 Component 过滤器并在同一场景规模下比较结果。
