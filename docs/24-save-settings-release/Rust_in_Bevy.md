# Rust in Bevy 24：错误传播与产品边界

发布构建会遇到读写失败、旧存档和缺失目录；这些都不是「理论上不该发生」的异常。产品代码必须为失败提供路径。

## 本章唯一主题

在持久化边界使用 `Result`、错误上下文和原子写入策略。

```rust
fn save(path: &std::path::Path, bytes: &[u8]) -> std::io::Result<()> {
    let temporary = path.with_extension("tmp");
    std::fs::write(&temporary, bytes)?;
    std::fs::rename(temporary, path)?;
    Ok(())
}
```

- `?` 保留失败控制流；调用方决定显示提示、重试或禁用功能。
- 临时文件后重命名可降低半写入文件的风险，仍应考虑目标平台与备份策略。
- 用户可编辑的数据、设置与存档都要在读取后验证版本和范围。

## 设计用法

将 I/O 留在适配层，游戏规则只接收已验证的设置或存档模型。release 前在干净环境验证资源路径、权限失败、首次启动和旧版本迁移。

## 练习

模拟保存目录不可写的情况，确认程序保留上一次存档并向玩家提供可理解的错误信息。
