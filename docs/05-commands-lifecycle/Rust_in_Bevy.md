# Rust in Bevy 05：延迟命令与世界修改边界

`Commands` 让你能生成实体，却不会把变化立刻塞进正在遍历的 World。这个延迟正是 ECS 能安全调度的代价与收益。

## 本章唯一主题

理解命令缓冲：系统把 `spawn`、`insert`、`despawn` 记录为请求，由调度器在合适边界应用。

```rust
fn spawn_enemy(mut commands: Commands) {
    commands.spawn((Enemy, Health(10)));
}
```

- `spawn` 返回的是可继续配置的 `EntityCommands`，不是已经可被当前 Query 枚举到的实体。
- 同一帧另一个系统何时看见改动取决于命令应用点和显式顺序。
- `Entity` 是轻量标识符，不拥有组件数据；实体被销毁后，保存的标识符可能失效。

## 设计用法

将「决定生成/销毁」与「读取生成结果」放在明确的调度边界两侧。若后续逻辑必须立即操作实体，保留 `Entity` id 并通过命令继续配置，别在同一系统中重新查询它。

Commands 适合结构变更；普通字段更新直接使用 `Query<&mut T>`，避免把每个数值赋值伪装成生命周期操作。

## 练习

生成一个带标记的实体，再在同一 `Commands` 链中插入初始组件。验证另一个系统何时才能查询到它。
